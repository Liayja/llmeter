## 0. 一句话定位

**基准一致性测试**用来回答一个问题：**我手上的第三方模型资源，和官方模型是不是同一个东西、行为是否等价？**

它用一份**官方基准快照**（跑一次存下来）作为标尺，之后每次只跑候选模型，逐条比对行为差异。

### 0.1 三个关键术语（先看这个）

| 术语 | 通俗解释 | 在本方案里的作用 | 例子 |
|------|----------|------------------|------|
| **闸门（Gate）** | "**资格审核**"：不满足就直接叫停，不给结论 | D0 可比性校验：参数/用例集/覆盖率对不上 → 判"不可比"，不进入打分 | 候选用了 `temperature=0.7`、基线是 `0` → 直接终止，提示"参数不一致，无法比较" |
| **阈值（Threshold）** | "**及格线**"：把数值差异划成几档（绿/黄/红）的分界点 | 每个维度内部用它把连续数值变成结论 | tokenizer 偏差 ≤1% 🟢；1~2% 🟠；>2% 🔴 |
| **权重（Weight）** | "**占比**"：汇总总分时，某个维度占总分的多少 | 仅用于生成"等价度分数"和排序、画雷达图；**不决定最终结论** | D3 指令遵循 10%、D8 结构 15% |

**三者关系**（一次典型运行的顺序）：

```
① 过闸门（D0 可比性校验）  → 不通过就结束，不给结论
② 每个维度按阈值判定 → 各自得出 🟢 / 🟠 / 🔴
③ 查一票否决（红旗）   → 命中即"不等价"
④ 命中 ≥2 个 🟠       → "可疑"
⑤ 全绿                → "等价"
   （权重只在这里参与：把各维度分数加权成 0~100 的"等价度"，用于排序和展示，不改变上面的结论）
```

> 为什么"有阈值还有红旗"？因为有些差异是**致命**的：比如 tokenizer 不同，基本可以断定不是同一套实现——
> 这种问题不能被"其他维度分数高"加权平均掉，所以单独设成一票否决。权重只用于"都不致命时"的排序参考。

## 1. 与压测的边界（必须分开的两个功能）

| 对比项 | **压测（Load Test）** | **基准一致性测试（Parity Test）** |
|--------|----------------------|-----------------------------------|
| 目的 | 测性能：QPS / TTFT / TPOT / 吞吐 / 成功率 | 测行为：是不是同一个模型、是否等价 |
| 请求特征 | 多并发、大量重复请求、长时间 | 少量、精心设计、逐条比对 |
| 输入 | 一个 prompt × N 次（或多场景矩阵） | 一个**用例集**（几十条分类用例） |
| 是否需要基线 | 不需要 | **必须有**官方基线 |
| 判定方式 | 统计指标（分布、分位数、阈值） | 行为类别 + 准确率 + 差异显著性 |
| 输出 | 性能报告（吞吐/延迟曲线） | 等价性报告（结论三档 + 红旗清单） |
| 典型时长 | 分钟~小时 | 几分钟（只跑候选） |
| 导航位置 | 压测 | **一致性基准（独立页签）** |

**结论：两者共用"连接 / 模型 / 提示词"资产，但作为两个独立功能模块，不混在同一个任务里。**

压测引擎与指标口径**不做任何改动**；一致性测试是新增的一套采集与判定逻辑。

## 2. 信息架构

```
平台
├── 压测            （现有：多并发大量请求，产性能指标）
├── 一致性基准      （新增，独立模块）
│   ├── 基准管理    建立/重建/查看/导出官方基准快照
│   ├── 候选测试    选基准 + 选候选 + 选维度 → 只跑候选 → 出报告
│   └── 对比报告    逐条对照 + 维度汇总 + 结论
└── 资产库          （现有：连接 / 模型 / 提示词 / 新增用例集）
```

## 3. 核心概念与数据模型

| 概念 | 说明 |
|------|------|
| **用例 Case** | 一条测试用例：维度、输入（messages / prompt / tools）、参数、期望行为、判定规则 |
| **用例集 CaseSet** | 用例的版本化集合（如 `parity-v1`，48 条 + 工具异常 16 条） |
| **基准 Baseline** | 官方模型跑一次的结果快照：用例集版本 + 参数指纹 + 每条输出 + usage + 行为类别 + 时间戳 |
| **候选运行 Candidate Run** | 只跑候选模型（第三方渠道 / 自建部署）的一次执行，与基准按 `case_id` 对齐 |
| **对比报告 Parity Report** | 逐条判定 + 维度汇总 + 红旗清单 + 结论（等价 / 可疑 / 不等价） |

### 数据表（建议）

```
case_sets      (id, name, version, description, created_at)
cases          (id, case_set_id, dimension, name, payload_json, expect_json, judge_rule, sort)
baselines      (id, name, model, connection_id, case_set_id, params_json, samples,
                created_at, notes, status[有效/过期])
baseline_items (baseline_id, case_id, run_index, output_text, usage_json,
                behavior_class, latency, prompt_tokens, created_at)
parity_runs    (id, name, baseline_id, model, connection_id, dimensions_json,
                params_json, status, created_at, finished_at)
parity_items   (run_id, case_id, run_index, output_text, usage_json,
                behavior_class, verdict, reason, latency)
```

> 输出文本量较大，`*_items` 也可落成 JSONL 文件（每份基线一个文件）+ 索引表。

> 实现补充（2026-09-20）：`*_items` 记录原始响应截断标记、输出文本截断标记和参数说明；
> 网络错误、401/403/429、5xx 统一作为不可判断证据，不进入等价性评分。

## 4. 测试维度总览（用户可选）

每个维度都是**可勾选项**，界面需展示三样信息：**这个测试用来干什么**、**多少条用例**、**预计多少请求 / 多久**。

| 编号 | 维度 | 权重 | 默认 | 这一项用来干什么（面向使用者的话术） |
|------|------|------|------|--------------------------------------|
| **D0** | 可比性校验 | 闸门 | 强制 | 先确认"这次对比有没有意义"：用例集、参数、覆盖率、基线新鲜度是否一致 |
| **D1** | 接口与参数语义 | 12% | ✅ | 确认 `max_tokens`、`temperature`、`thinking`、`stop` 这些参数在该渠道**是否真的生效**（不是收下就算） |
| **D2** | 指纹一致性 | 20% | ✅ | 通过 tokenizer / usage / 响应字段的指纹，判断上游**是不是同一套实现**——这是最难伪造的证据 |
| **D3** | 指令遵循 | 10% | ✅ | 能不能老老实实按格式、字数、禁用词等约束输出 |
| **D4** | 知识事实 | 7% | ⬜ | 同等知识水平，看有没有换成旧版本或小模型 |
| **D5** | 推理与数学 | 9% | ⬜ | 多步推理能力是否同一档，看是否被蒸馏/降级 |
| **D6** | 代码能力 | 7% | ⬜ | 生成的代码能不能跑通（可执行验证 pass@1） |
| **D7** | 长上下文 | 5% | ⬜ | 上下文窗口有没有被偷偷缩小、长文关键信息能否召回 |
| **D8** | 结构与工具调用 | 15% | ✅ | JSON 输出、function calling 在 agent 场景是否还可用 |
| **D9** | 协议健壮性（孤儿 tool 等） | 10% | ✅ | 异常对话序列下，渠道是**严格报错、静默丢弃还是偷偷修复**——对 agent 影响最大 |
| **D10** | 边界行为 | 3% | ⬜ | 超长输入、超限参数、错误响应的处理方式是否与官方同类 |
| **D11** | 风格指纹 | 2% | ⬜ | 从输出长度、格式习惯、用词套路判断"像不像同一个模型" |
| **D12** | 性能旁证 | 不计分 | ⬜ | 只看 TTFT / TPOT / 缓存命中分布是否异常（**不作等价性判据**） |

> 权重合计 **100%**（D0 闸门与 D12 旁证不计分），可在配置中自由调整，保存时自动归一化；也可整体关闭加权总分，只保留维度判定与红旗（见 7.4）。

### 推荐组合（界面上一键选择）

| 组合 | 包含维度 | 用途 | 规模 |
|------|----------|------|------|
| **精简** | D1 + D2 + D9 | 快速判断"是不是同一套实现" | ~44 条用例 |
| **推荐**（默认） | 精简 + D3 + D8 | 常规第三方资源验收 | ~60 条 |
| **全面** | 全部维度 | 重要供应商入场 / 换版复验 | ~90 条 |

## 5. 各维度详细设计

> 判定阈值均为**默认建议值**，可在配置中调整。

### D0 可比性校验（闸门，不可选）

| 检查项 | 通过条件 | 不通过 |
|--------|----------|--------|
| 用例集一致 | 版本 + 条数一致 | 终止，提示选错基线 |
| 参数指纹一致 | temperature / max_tokens / thinking / top_p / stop / seed 完全相同 | 终止，列出差异项 |
| 基线覆盖率 | ≥95% 用例有基线输出 | 报告标注未覆盖项，不出总评 |
| 基线新鲜度 | 默认 ≤30 天 | 出结论但标"基线可能过期" |
| 必备字段 | usage 的 prompt/completion tokens 存在 | 指纹层降级为不可判 |

### D1 接口与参数语义

| 检查项 | 方法 | 判据 |
|--------|------|------|
| `max_tokens` 生效性 | 设 256，观察 `completion_tokens` | 违规率 >5% 🟠；>20% 🔴 |
| `temperature` 生效性 | temp=0 与 temp=1 各 3 次，比离散度 | 无差异 🟠（参数被忽略） |
| `thinking` / `reasoning_effort` | 切换取值看 `reasoning_tokens` 与延迟 | 不生效 🟠；完全不支持 🔴 |
| `stop` 序列 | 设置后观察是否在指定处截止 | 不生效 🟠 |
| `system` 角色尊重度 | system 要求"只用英文回答" | 通过率差 >20pp 🟠 |
| `stream_options.include_usage` | 流式尾帧是否带 usage | 不支持 🟠 |

### D2 指纹一致性（最硬的证据）

| 子项 | 方法 | 判据 |
|------|------|------|
| tokenizer 指纹 | 20 段文本（中/英/代码/emoji/特殊符号/长文）比 `prompt_tokens` | 均值偏差 ≤1% 🟢；1~2% 🟠；>2% 🔴 |
| 模板指纹 | 固定 system+user+多轮，比较 token 差是否为**恒定偏移** | 随机偏移 🟠 |
| usage 字段齐全度 | `cached_tokens` / `reasoning_tokens` / `completion_tokens_details` | 官方有候选无 🟠；核心字段缺 🔴 |
| 响应元数据 | `model` 字段、`id` 前缀、限流头 | 记录为辅助证据 |

### D3 指令遵循

- 用例：字数精确、只输出 JSON、禁用词、多约束组合、格式模板填充。
- 指标：规则校验通过率。
- 判据：通过率差 >5pp 🟠；>10pp 🔴。

### D4 知识事实

- 用例：有唯一答案的事实题，含中英文、含时效性（用来暴露版本新旧）。
- 指标：准确率（精确/归一化匹配），配对 McNemar 检验。

### D5 推理与数学

- 用例：多步计算、逻辑推理，有唯一解。
- 指标：准确率 + 配对检验。
- 意义：蒸馏/小模型替换在这一维度最明显。

### D6 代码能力

- 用例：函数实现 + 单测，沙箱执行。
- 指标：pass@1。

### D7 长上下文

- 用例：把关键信息埋在 3k / 10k / 20k / 50k 文档的不同位置。
- 指标：召回率矩阵（长度 × 位置）。
- 意义：发现被缩水的上下文窗口、注意力退化。

### D8 结构与工具调用

| 检查项 | 指标 | 判据 |
|--------|------|------|
| JSON 输出 | parse 成功率、schema 通过率 | 差 >10pp 🟠 |
| function calling | 工具名匹配率、参数 schema 匹配率、`tool_call_id` 回填 | 不可用 🔴 |
| 并行/多轮工具链 | 两轮工具链跑通率 | 中途断裂 🔴 |
| 流式工具分片 | delta 拼接正确率 | 参数丢失 🟠 |

### D9 协议健壮性（孤儿 tool 等异常序列）

**判定方式特殊：不比文本，比"行为类别"。**

| 行为类别 | 含义 | 风险 |
|----------|------|------|
| `REJECT` | 400/422 + 明确的错误类型 | 🟢 可预期 |
| `ACCEPT_AS_IS` | 200，原样透传 | 🟢 与官方一致 |
| `ACCEPT_REPAIRED` | 200，但上游被改写（丢/补/重排） | 🟠 静默修复，掩盖 agent bug |
| `ERROR_OTHER` | 500/502/超时/挂起 | 🟠 |
| `UNKNOWN` | 异常格式 / 无响应 | 🔴 |

| # | 用例 | 观察点 |
|---|------|--------|
| T1 | **孤儿 tool 结果**（无对应 `tool_calls`） | 400 还是静默接受 |
| T2 | `tool_call_id` 不匹配 | 是否校验 id |
| T3 | 悬空 `tool_calls`（缺结果，直接跟 user） | 是否要求配平 |
| T4 | 重复 tool 结果 | 接受/报错/取第一条 |
| T5 | 结果顺序与 `tool_calls` 不一致 | 重排还是报错 |
| T6 | `tool_choice` 指向不存在的工具 | 400 还是忽略 |
| T7 | 历史含 `tool_calls` 但未声明 `tools` | 是否报错 |
| T8 | tool 结果 content 非字符串 | 接受/报错 |
| T9 | 历史 tool arguments 为非法 JSON | 是否校验历史 |
| T10 | 并行 tool_calls + 两个结果 | 并行支持度 |
| T11 | 两个 tool_calls 只回一个结果 | 是否报错 |
| T12 | `tools: []` / `tool_calls: []` | 兼容性 |
| T13 | 超长 tool 结果（几十 KB） | 截断/报错 |
| T14 | 流式 tool_calls 分片拼接 | 参数完整性 |
| T15 | tool 结果后紧跟 system | 序列合法性 |
| T16 | 上轮未闭合 + 新任务开始 | 多轮脏状态处理 |

**附加硬检测**：把"非法序列"和"等价合法序列"各跑一次，比较 `prompt_tokens`：

- 基本相同 → 非法部分被丢弃（静默修复）
- 明显变大 → 被补全成合法结构
- 直接报错 → 严格校验

判据：行为类别一致率 ≥95% 🟢；80~95% 或出现 `ACCEPT_REPAIRED` 🟠；<80% 或 T1~T3 与官方完全相反 🔴。

### D10 边界行为

- 超长输入 / 超限 `max_tokens` / 空输入 / 特殊字符 / 错误响应结构（401、404、429）。
- 判据：行为类别不同（官方报错、候选静默截断）🟠。

### D11 风格指纹

- 输出长度分布（均值/方差/分位）、格式习惯（Markdown、列表、emoji）、开头结尾套路、拒答模板。
- 方法：分布检验（KS / JS 散度）+ 语义相似度；显著差异 🟠。

### D12 性能旁证（不计分）

- TTFT / TPOT / 吞吐 / 缓存命中率分布。
- 只用于提示异常：TPOT 异常快可能被量化降级；`cached_tokens` 恒 0 说明未实现缓存；TTFT 双峰说明背后多节点。
- **明确不参与等价性判定**（性能差异通常来自基础设施）。

## 6. 采样与统计协议

| 项 | 规定 |
|----|------|
| 温度 0 用例 | 基线 1 次、候选 1 次（必要时各 3 次验证确定性） |
| 业务温度用例 | 基线 N=5、候选 N=5，比较**分布**（众数占比、相似度均值±std） |
| 顺序 | 串行优先；并发仅作交叉验证 |
| 缓存 | 指纹类用例开 `unique_prefix` 避免"缓存导致的假一致"；性能旁证保留缓存 |
| 统计 | 比例类给 Wilson 置信区间；配对题用 McNemar；连续量用 Wilcoxon |
| 记录 | 时间戳、`prompt_tokens`、usage 全字段、响应头（渠道痕迹） |

## 7. 判定与结论

### 一票否决（🔴，命中任一即"不等价"）

1. tokenizer 指纹平均偏差 >2%
2. 官方特有字段/参数完全不支持（`thinking`、`reasoning_tokens` 等全缺失）
3. 工具调用完全不可用
4. 能力维度准确率差 >10pp 且统计显著
5. `max_tokens` 系统性不遵守（违规率 >20%）
6. D9 中 T1~T3 的行为类别与官方完全相反

### 结论聚合

| 条件 | 结论 |
|------|------|
| 命中任一 🔴 | **不等价** |
| ≥2 个维度 🟠 | **可疑**（需人工复核） |
| 全部 🟢 | **等价** |
| D0 校验不通过 | **不可比**（不出结论，首屏给出原因与建议操作） |

> 加权总分默认开启，但**只用于排序与展示**；结论必须**维度化 + 红旗清单**。总分可在配置中关闭（见 7.4）。

### 7.3 闸门不通过时的报告呈现

闸门不通过**必须写清原因，并给出可执行建议**，不能只显示"失败"。报告首屏固定为三段：**结论（不可比）+ 原因 + 建议操作**。

| 检查项 | 触发条件 | 报告提示（示例文案） | 建议操作（按钮） |
|--------|----------|----------------------|------------------|
| 用例集不一致 | 用例集版本或条数不同 | 「用例集不一致：基线 parity-v1（60 条）／本次 parity-v2（72 条），其中 **48 条可对齐**」 | `只对比可对齐的 48 条`（报告中标注）／`重选基线` |
| **参数指纹不一致** | 任一生成参数不同 | 「参数不一致，无法比较：temperature（基线 0 → 候选 0.7）；max_tokens（基线 256 → 候选 1024）」 | `用基线参数重跑候选`（一键）／`忽略并继续`（报告标注"参数不一致，结论仅供参考"） |
| 覆盖率不足 | 有基线输出的用例 <95% | 「48/60 条用例缺少基线输出：输入-20k、代码-01 …（可下载完整清单）」 | `补齐基线`（只跑缺失用例）／`仅对比 48 条` |
| 基线过期 | 超过有效期（默认 30 天） | 「基线创建于 45 天前（2026-08-01），官方模型可能已变更」 | `重建基线`／`继续对比`（报告标注"基线可能过期"） |
| 缺少 usage 字段 | 候选响应无 `prompt_tokens` 等 | 「候选缺少 usage.prompt_tokens，**D2 指纹维度降级为不可判**，其余维度不受影响」 | `跳过指纹维度`／`检查渠道实现` |
| 候选鉴权/连通失败 | 401/404/连接超时 | 「候选连接不可用：HTTP 401（API Key 无效）」 | `测试连接`／`编辑连接` |

**规则**：

- 闸门不通过 → **不显示等价度分数**，只显示"不可比 + 原因 + 建议"；
- 若用户选择"忽略并继续"，报告顶部**永久标注**该偏离（如"参数不一致，结论仅供参考"），且不计入正式基线档案。

### 7.4 配置项（开关 / 权重 / 阈值，均可自定义）

配置分三层，优先级从高到低：**本次运行 > 用例集默认 > 平台默认**；每次运行的**配置快照写入报告**，保证结论可复现。

**① 开关类**

| 配置项 | 默认 | 说明 |
|--------|------|------|
| 启用加权总分 | **开** | 关闭后报告只展示维度判定与红旗，不显示 0~100 分数与雷达图 |
| 启用一票否决 | **开** | 关闭后红旗降级为 🟠（不推荐关闭，会掩盖致命差异） |
| 闸门不通过时允许忽略继续 | 开 | 关闭则闸门不通过直接终止，不允许强行出报告 |
| 基线过期提醒 | **30 天** | 超过则报告首屏提示，可一键重建 |
| 启用性能旁证维度 | 关 | 开启后展示 TTFT/TPOT/缓存分布，**仅参考不计分** |
| 指纹用例去缓存 | **开** | 指纹类用例自动加唯一前缀，避免缓存导致的"假一致" |

**② 权重类**（D0 为闸门不参与计分；关闭"加权总分"后本组无效）

| 维度 | D1 | D2 | D3 | D4 | D5 | D6 | D7 | D8 | D9 | D10 | D11 | 合计 |
|------|----|----|----|----|----|----|----|----|----|-----|-----|------|
| 默认权重 | 12% | 20% | 10% | 7% | 9% | 7% | 5% | 15% | 10% | 3% | 2% | **100%** |

> 权重可自由调整，保存时**自动归一化到 100%**；D12 性能旁证不参与加权。

**③ 阈值类**（每档均可单独调整）

| 维度 | 指标 | 🟢 | 🟠 | 🔴 |
|------|------|----|----|----|
| D1 | `max_tokens` 违规率 | ≤5% | 5~20% | >20% |
| D1 | 参数完全不被支持 | — | 部分不支持 | 核心参数不支持 |
| D2 | tokenizer `prompt_tokens` 平均偏差 | ≤1% | 1~2% | >2% |
| D3 | 指令遵循通过率差 | ≤5pp | 5~10pp | >10pp |
| D4 | 知识准确率差 | ≤5pp | 5~10pp | >10pp |
| D5 | 推理准确率差 | ≤5pp | 5~10pp | >10pp |
| D6 | 代码 pass@1 差 | ≤5pp | 5~10pp | >10pp |
| D7 | 长文召回率差 | ≤5pp | 5~15pp | >15pp |
| D8 | 结构/工具调用通过率差 | ≤5pp | 5~10pp | >10pp 或工具不可用 |
| D9 | 行为类别一致率 | ≥95% | 80~95% | <80% |
| D10 | 边界行为类别一致率 | ≥95% | 80~95% | <80% |
| D11 | 风格分布差异（JS 散度） | ≤0.1 | 0.1~0.2 | >0.2 |
| 红旗 | 一票否决清单（见上） | — | — | 可整体开关 |

**④ 采样类**

| 配置项 | 默认 |
|--------|------|
| 温度 0 用例采样次数 | 1（可选 3 次验证确定性） |
| 业务温度用例采样次数 | 5 |
| 执行方式 | 串行优先（并发仅作交叉验证） |
| 超时 / 重试 | 沿用所选模型连接的配置 |

## 8. 界面设计

### 8.1 基准管理（Baseline）

列表字段：名称 / 官方模型 / 用例集版本 / 用例数 / 采样次数 / 创建时间 / 新鲜度 / 状态。
操作：`建立新基准`、`重建`、`查看明细`、`导出`、`标记过期`。

### 8.2 候选测试（三步向导）

**第一步：选基准**

下拉选择已有基线，展示：`glm-5.3-official@2026-09-15 · 用例集 parity-v1 · 60 条 · 采样 1 次 · 建立于 3 天前`。

**第二步：选候选**

选择连接 + 模型（支持多选 → 一个基线对多个候选，横向对比）。

**第三步：选维度（可勾选，核心交互）**

每个维度一张卡片，包含三行信息：

```
☑ 接口与参数语义                          8 条 · 约 16 次请求 · ~1 分钟
   用来确认 max_tokens / temperature / thinking 等参数在该渠道是否真的生效

☑ 指纹一致性                             20 条 · 约 20 次请求 · ~2 分钟
   通过 tokenizer / usage 指纹判断上游是否同一套实现（最难伪造的证据）

☑ 协议健壮性（孤儿 tool 等）              16 条 · 约 32 次请求 · ~3 分钟
   异常对话序列下，渠道是严格报错、静默丢弃还是偷偷修复——对 agent 影响最大

☐ 长上下文                                4 条 · 约 8 次请求 · ~2 分钟
   验证上下文窗口是否被缩小、长文关键信息能否召回
```

顶部提供三个快捷按钮：`精简组合`、`推荐组合`、`全选`；下方实时显示**本次预计请求数 / 预计耗时 / 预计 token 消耗**。

**高级设置（抽屉，可折叠）**——对应 7.4 的配置项，本次运行的设置优先于平台默认：

| 分组 | 可调项 |
|------|--------|
| 开关 | 启用加权总分、启用一票否决、闸门不通过是否允许忽略继续、指纹用例去缓存、是否启用性能旁证维度 |
| 权重 | 各维度权重（默认见 7.4，保存时自动归一化到 100%） |
| 阈值 | 各维度的 🟢/🟠/🔴 分界值（默认见 7.4） |
| 采样 | 温度 0 采样次数、业务温度采样次数 N、执行方式（串行/并发） |
| 基线 | 有效期天数（默认 30 天） |

> 面板底部提供 `恢复默认` 与 `保存为用例集默认`；本次运行的配置会写入报告，便于复现与对比。

### 8.3 运行页

- 按维度显示进度：`D2 指纹 12/20`、`D9 协议健壮性 5/16`
- 支持中止（已跑维度保留结果）
- 实时显示"当前用例 + 已判定结果"（通过/偏离计数）

### 8.4 报告页

1. **结论卡**：等价 / 可疑 / 不等价 + 红旗清单（≤3 条，可点击跳到证据）；
   若闸门不通过，则显示 **"不可比" + 具体原因 + 建议操作按钮**（见 7.3），且不显示等价度分数
2. **可比性校验**：用例集、参数指纹、覆盖率、基线时间
3. **维度总表**：每维度得分 / 阈值 / 颜色
4. **偏离 Top-N**：官模与候选输出并排 + 判定依据
5. **指纹明细**：tokenizer 对照表、usage 字段对照、参数生效矩阵
6. **协议健壮性矩阵**：16 条用例 × 行为类别（官方 vs 候选）
7. **性能旁证**：TTFT/TPOT/缓存分布对比（标注"不参与判定"）
8. **附录**：全部用例逐条对照，可导出 Excel

> 报告首部固定附上**本次使用的配置快照**（权重、阈值、开关、采样次数、基线版本），确保任何结论都可复现、可追溯。

## 9. 执行流程

```mermaid
flowchart LR
  A["建立基准<br/>官方模型跑一次"] --> B["保存基线快照<br/>输出+usage+行为类别"]
  B --> C["选择候选<br/>第三方连接/模型"]
  C --> D["勾选测试维度"]
  D --> E["只跑候选<br/>按用例集执行"]
  E --> F["按 case_id 与基线对齐"]
  F --> G["逐条判定 + 维度汇总"]
  G --> H["等价性报告<br/>等价/可疑/不等价"]
  B -.->|多个候选共用| C
```

关键点：

- **官模只跑一次**，之后每次只跑候选；
- 多个候选共用同一基线 → 横向可比；
- 基线有效期（默认 30 天）到期提醒重建；
- 可选"官方漂移巡检"：低频跑少量探针用例，检测官方是否已变更。
