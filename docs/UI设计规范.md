## 1. 定位与目标

### 1.1 现状（为什么要重做前端）

当前前端是**无构建的原型**：`index.html` 228 行、`app.css` 100 行、`app.js` 900 行（全部用 `innerHTML` 拼字符串），对应后端 38 个 API。
反复出现的界面问题（弹窗关不掉、面板不折叠、页面被拉长、响应体难以阅读、下拉空白无提示）都源于缺少组件层、设计令牌与状态规范。

### 1.2 目标风格：**紧凑专业 · 高信息密度 · 不杂乱**

> 使用者要的是"**一屏掌握所有关键信息**"的掌控感，而不是留白很多的营销页。

| 要 | 不要 |
|---|---|
| 高密度但分组清晰（分区、分隔线、表头层级） | 大圆角、大留白、装饰性插画 |
| 数字与状态用颜色/徽标表达，一眼可辨 | 用颜色做装饰、每处颜色都不同 |
| 详情走抽屉，主视图不被打断 | 详情在页面下方无限延伸 |
| 同一操作在任何页面长得一样 | 每个页面各自发明控件样式 |

## 2. 技术选型（路线 B）

| 项 | 选择 | 说明 |
|---|---|---|
| 框架 | **Vue 3**（Composition API + `<script setup>`） | 组件化、状态清晰 |
| 构建 | **Vite** | 本地 `npm run build` 产出静态文件 |
| 组件库 | **Element Plus** | 表格/表单/抽屉/弹窗/通知/校验开箱即用，中文文档完善 |
| 状态 | **Pinia** | 连接/模型/任务等共享状态 |
| 路由 | **Vue Router**（hash 或 history 模式） | 四个页面 + 抽屉路由（可选） |
| 图表 | **ECharts**（P2 阶段引入） | 结果页曲线 |
| 部署 | 构建产物 `app/web/dist`，由 FastAPI 挂载到 `/` | **后端 API 完全不变**；旧静态页保留为 `/legacy` 兜底 |

依赖以**本地安装**为准（不走 CDN），保证离线可用。

## 3. 布局范式

### 3.1 三段式骨架（所有页面统一）

```
┌───────────┬──────────────────────────────────────┬──────────────┐
│ 左侧导航   │  顶部工具栏（页标题 / 筛选 / 主操作）    │  右侧抽屉     │
│ (56~200px)│                                      │  (420~720px) │
│           │  主工作区（表格 / 表单 / 图表）          │  详情/编辑/    │
│ 压测       │                                      │  报告         │
│ 一致性基准 │                                      │  (可关闭)     │
│ 资产库     │                                      │              │
│ 结果       │                                      │              │
└───────────┴──────────────────────────────────────┴──────────────┘
```

- 左侧导航可折叠（仅图标 / 图标+文字），默认展开；
- **详情、编辑、报告、调试一律用右侧抽屉**，不占用主页面高度，支持 Esc / 点遮罩 / 关闭按钮收起；
- 同一时刻只允许一个抽屉打开；抽屉切换时替换内容，不叠加。

### 3.2 页面结构规范

| 页面 | 结构 |
|---|---|
| 压测 | 顶部工具栏（模型多选、运行/中止）＋ 左：参数面板（分组折叠）＋ 右：结果与实时进度 |
| 一致性基准 | 顶部步骤条「① 建立基线 → ② 候选测试 → ③ 对比报告」；主体左列表右详情（抽屉） |
| 资产库 | 三个 Tab（连接 / 模型 / 提示词与场景），表格主视图 + 行内操作 + 抽屉编辑 |
| 结果 | 左侧结果列表（可筛选）＋ 右侧报告面板（指标卡、维度表、用例下钻） |

## 4. 设计令牌（Design Tokens）

统一在 `styles/tokens.scss` 定义，Element Plus 主题变量同步覆盖（`--el-color-primary` 等）。

| 类别 | 令牌 | 值 |
|---|---|---|
| 主色 | `--c-primary` | `#2f5496`（沿用现有品牌蓝） |
| 语义色 | `--c-success / --c-warning / --c-danger` | `#2e7d32 / #e65100 / #c62828` |
| 中性色 | `--c-text-1/2/3` | `#1f2937 / #4b5563 / #9aa4b2` |
| 背景 | `--c-bg / --c-surface / --c-surface-2` | `#f5f7fa / #ffffff / #fafbfd` |
| 边框 | `--c-border` | `#d9dee5`（1px，统一） |
| 状态底 | `--c-success-bg / warning-bg / danger-bg` | `#e8f5e9 / #fff4e5 / #fdecea` |
| 间距 | `--sp-1..6` | `4 / 8 / 12 / 16 / 24 / 32` |
| 字号 | `--fs-xs/sm/base/lg/xl` | `12 / 13 / 14 / 16 / 20` |
| 行高 | 表格/表单 | `1.5`；紧凑模式表格行高 `32px` |
| 圆角 | `--r-sm/md/lg` | `4 / 6 / 8`（抽屉/弹窗用 8） |
| 阴影 | `--sh-card / --sh-pop` | `0 1px 2px rgba(0,0,0,.04)` / `0 8px 24px rgba(0,0,0,.12)` |

**密度要求**：表格行高 32px、卡片内边距 12px、表单控件高度 28~32px；信息多时可滚动，不用大留白换空间。

## 5. 组件规范（Element Plus 为主，缺失的自行封装）

| 组件 | 规范要点 |
|---|---|
| Table | 固定表头、斑马纹、悬浮高亮、列宽策略（固定关键列 + 自适应）、长文本省略 + 悬浮完整值、空态插槽 |
| Drawer | 右侧 480px（详情）/ 720px（报告、请求响应）；标题栏固定，底部操作区固定，中间滚动 |
| StatCard | 大号数字（20px）+ 标签（12px）+ 状态色；一行 4~6 个 |
| Tag / Badge | 语义色映射：🟢 通过 `success`、🟠 可疑 `warning`、🔴 不通过 `danger`、灰 `info` |
| CodeBlock | 等宽字体、JSON 美化、行号可选、右上角「复制」、超长折叠（默认展示前 40 行） |
| KV 描述列表 | 两列紧凑布局，用于单条记录元信息（替代大段 JSON） |
| Progress | 线性进度 + 文字（已用/总量/百分比/当前项）；>2s 的操作必须显示 |
| Toast / Notification | 成功用 message（3s 自动消失），失败用 notification（含原因与建议，手动关闭） |
| Empty / Skeleton | 每个列表和详情都要有：空态给出"下一步做什么"，加载态用骨架屏 |
| Confirm | 危险操作（删除、覆盖基线）必须二次确认，按钮上写清动作 |

## 6. 交互规范

1. **异步四态**：loading / empty / error / success 必须齐备，不允许"点了没反应"。
2. **错误可执行**：错误信息 = 现象 + 原因 + 建议（例："Base URL 未配置 → 去编辑连接"）。
3. **长内容默认折叠**：详情、请求体、响应体、报告附表都可展开/收起，默认收起。
4. **键盘**：`Esc` 关抽屉/弹窗；`Ctrl/Cmd + K` 全局搜索（后续）；表格 `↑↓` 导航（后续）。
5. **复制友好**：请求体、响应体、命令、路径都提供一键复制。
6. **危险操作**：删除类操作二次确认；不可逆操作在确认框里写明影响。
7. **反馈不打断**：短任务用 Toast，长任务用进度条 + 可中止。
8. **一致性**：同名操作在任何页面用同样的图标、措辞与位置。
9. **日志与指标分离**：持续变化的数值放在实时指标卡；运行日志只记录启动、场景切换、阶段性进度、重试、异常和完成摘要。ETA 只在指标卡中作为粗略估算展示，不作为每轮日志字段。
10. **运行任务保活**：压测页面在路由切换时必须保活 SSE、进度和日志；页面刷新后通过 `sessionStorage` 恢复最近任务并重新连接后台状态，不能出现“后台还在跑但页面全部丢失”的假死状态。
11. **阶梯输入矩阵**：场景模式支持多个并发点，按模型 × 场景 × 并发点顺序执行；结果表必须展示目标输入 token、实际输入 token 和偏差，并在输入长度梯度报告中给出 TTFT/延迟的每 1k token 增量。
12. **重试可追溯**：运行日志中的每次重试必须显示请求序号、失败次数、HTTP 状态/连接错误、服务端错误摘要和退避时间，不能只显示“发生了一次重试”。

## 7. 页面级设计要点

### 7.1 压测
- 顶部：模式切换（场景对比 / 单次压测）、模型多选、`运行` / `中止`；
- 左栏参数分组折叠：基础 / 高级 / 输出；
- 右栏实时：进度条 + `完成/总数`、速率、TTFT、平均延迟、ETA、失败数；日志可折叠；
- 「先试跑一次」走抽屉，展示请求体与结构化响应。

### 7.2 一致性基准
- 步骤条：`① 建立基线 → ② 候选测试 → ③ 对比报告`，当前步骤高亮，可回退查看；
- 基线列表表格列：名称 / 模型 / 状态 / 用例数 / 覆盖率 / 建立时间 / 新鲜度 / 操作；
- 维度选择：卡片式复选，每张卡片显示**用途说明 + 用例数 + 预计请求数与耗时**（沿用现行文案）；
- 报告：结论徽标 + 红旗清单 + 维度表 + 用例列表（点击行 → 右侧抽屉展示原始请求与响应）；
- **原始响应优先**：直接展示美化后的完整 JSON，不额外拆成多块小表格；4xx 保留原始报错体。

### 7.3 资产库
- 三个 Tab：连接 / 模型 / 提示词与场景；
- 表格行内操作：编辑 / 测试 / 调试 / 删除；
- 编辑走抽屉（表单 + 校验），密钥字段显示脱敏值，留空表示不修改。

### 7.4 结果
- 左侧列表（按日期/模型筛选）+ 右侧报告（指标卡 + 对比表 + 图表位）；
- 报告内所有明细可下钻到抽屉；导出按钮固定在报告右上角。

## 8. 迁移计划（后端 API 不动）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M1 基建** | Vue3 + Vite + Element Plus 工程、tokens、布局骨架、路由与 API 客户端 | 四个页面路由可切换，主题与令牌生效 |
| **M2 结构改造** | 抽屉范式、四态规范、表格与详情组件落地 | 详情/编辑/报告全部走抽屉；无"点了没反应" |
| **M3 页面迁移** | 资产库 → 压测 → 一致性基准 → 结果，逐页对齐现有功能 | 每页功能与旧版一致，视觉统一 |
| **M4 视觉打磨** | 密度调整、语义色、图表（ECharts）、深浅色 | 一屏信息量达到"掌握全局"且不杂乱 |
| 切换 | 构建产物挂载 `/`，旧页保留 `/legacy` | 回滚开关可用（改一行配置即可切回旧版） |
